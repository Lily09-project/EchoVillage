# Echo Village 2.0 — 驗收規格

本文件在重做開始前訂定，是判斷專案「完成」的唯一標準。每一條驗收項目都對應到可自動執行的測試，
最終 PR 必須逐條附上證據（測試名稱或 CI job），全部通過才算完成。

## 0. 範圍與架構決策

| 項目 | 決策 |
| --- | --- |
| 引擎 | 維持 Godot 4.5.2 stable、GL Compatibility 渲染器 |
| 平台 | 保留 Windows 桌面版，**新增網頁版**（Godot Web 匯出、單執行緒模式，不需要特殊伺服器標頭），部署於 GitHub Pages，面試官點連結就能玩 |
| AI | 全部離線、可重現：Utility AI、傳聞傳播、程序化任務與文法式對話都由本地規則與固定種子驅動，不需要 API 金鑰 |
| 相容性 | 既有存檔可透過遷移升級到新版本，不能讓舊存檔失效 |

## 1. 功能驗收（創新功能）

### F1 網頁版即點即玩
- 以 Web 匯出模板產生 `index.html`／`.wasm`／`.pck`，部署在 GitHub Pages 的子路徑下。
- 在瀏覽器中載入、進入主選單、開始新遊戲；瀏覽器的存檔寫入使用者端的 IndexedDB。
- 驗收：Playwright 在 Chromium 開啟網頁版，canvas 成功繪製（非全黑畫面），且沒有引擎載入錯誤。

### F2 傳聞傳播網路
- NPC 會依關係中的信任與好感，把記憶當作「傳聞」傳給其他 NPC；每次轉述都有機率失真（強度衰減、細節改變），並記錄傳播鏈。
- 新增「傳聞網路」面板：以節點與連線呈現誰知道哪個傳聞、從誰聽來、可信度多少。
- 驗收（單元測試）：
  - 同種子下傳播結果完全相同；
  - 信任低於門檻的關係不傳播；
  - 每次轉述強度遞減，且不會無限循環；
  - 傳播鏈可完整回溯到原始事件。

### F3 湧現式任務
- 依 NPC 未被滿足的需求、彼此衝突與傳聞內容，程序化產生委託（例如「替鮑伯澄清被誤傳的流言」）。
- 每個任務都通過資料驗證，完成後實際改變關係、聲望或物品。
- 驗收：
  - 產生的任務引用的 NPC、物品與地點都存在；
  - 相同世界狀態與種子產生相同任務；
  - 不可完成的任務不會被產生；
  - 完成後的效果符合定義。

### F4 記憶驅動對話
- 以文法樹與 NPC 個性、目前情緒、記憶與傳聞組合出對話，讓同一個 NPC 在不同情境說出不同、有依據的話。
- 驗收：
  - 所有產生的句子都沒有未填入的變數；
  - 句中提到的人物與事件確實存在於 NPC 的記憶中；
  - 同種子結果相同；
  - 長度在 UI 可容納範圍內。

### F5 介面與體驗重做
- 重新設計主選單、HUD、面板與新手引導，統一視覺語言。
- 新增無障礙選項：字級縮放、色盲友善配色、減少動態。
- 驗收：視覺 QA 截圖矩陣（4 種解析度）全部更新並通過；新增選項會被保存，重新啟動後仍有效。

### F6 村落日誌
- 每天結束時根據因果歷程與傳聞網路，自動寫出一段當日故事摘要，可回顧歷史天數。
- 驗收：摘要只引用當天確實發生的事件；沒有事件時顯示明確的空狀態。
