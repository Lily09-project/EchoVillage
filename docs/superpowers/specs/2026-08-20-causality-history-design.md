# Echo Village v1.4 關係與故事歷程設計

日期：2026-08-20  
狀態：已核准執行（依產品方向授權，由 Codex 選擇最推薦方案）

## 問題

Echo Village 已能讓玩家與居民互動、建立記憶、改變信任與好感、解鎖村落編年並做出 Living Stories 分支選擇。然而，這些結果分散在居民卡、事件紀錄、故事面板與每日回音中。玩家知道「發生了什麼」，卻不容易回答：

- 哪一次互動改變了某位居民？
- 關係數值改變前後是多少？
- 某段記憶是如何留下的？
- 哪個故事選擇造成現在的局面？

這也讓作品集審查者較難快速理解模擬系統的可解釋性與資料流。

## 目標

新增「關係歷程 / CAUSALITY」檢視，將既有時間軸提升為可追溯的因果紀錄：

1. 關係改變記錄居民、對象、改變量與前後值。
2. 記憶建立記錄居民、主體、事件類型、重要度與情緒值。
3. 故事選擇記錄故事線、選項與是否完成。
4. 玩家可以依居民與類型篩選最近紀錄。
5. 舊存檔與既有無結構化欄位的時間軸仍可正常載入。
6. 所有資料均有邊界限制、深拷貝與輸入正規化，避免存檔污染與無限成長。

## 方案比較

### A. 建立獨立關係歷史資料庫

優點是資料模型單純；缺點是會與既有 `timeline_events` 重複儲存，增加同步與遷移成本。

### B. 擴充既有時間軸（採用）

在既有事件上加入可選的 `effect_kind`、`actors`、`effect` 欄位。舊事件維持可讀，新事件能提供完整因果資料；每日回音與關係歷程共用同一份真實來源。

### C. 僅解析文字紀錄

開發快，但無法可靠取得前後值、故事 ID 或記憶重要度，也不具備可維護性。

## 資料設計

結構化欄位皆為可選，確保向後相容：

```gdscript
{
  "id": "echo_42",
  "day": 3,
  "minute": 615,
  "time": "第 3 天 10:15",
  "phase": "Morning",
  "location": "village_square",
  "category": "social",
  "message": "艾莉絲對玩家：信任 +4、好感 +6",
  "effect_kind": "relationship",
  "actors": ["alice", "player"],
  "effect": {
    "npc_id": "alice",
    "target_id": "player",
    "changes": {"trust": 4.0, "affinity": 6.0},
    "before": {"trust": 10.0, "affinity": 8.0},
    "after": {"trust": 14.0, "affinity": 14.0}
  }
}
```

限制：事件最多保留 160 筆；actors 最多 4 個、每個 ID 最長 64 字元；effect 最多 16 個鍵；查詢筆數限制 1–50；所有回傳資料深拷貝。

## 架構

- 新增 `CausalityHistoryService`，負責欄位正規化、事件查詢、顯示摘要與存檔驗證。
- `GameManager` 仍是唯一狀態擁有者，負責事件序號、遊戲時間與持久化。
- `change_relationship` 在套用前後擷取快照並記錄結構化事件。
- `create_memory` 與 `choose_story_arc` 寫入對應的結構化事件。
- `main.gd` 僅負責模式狀態、篩選操作與呈現，不重複實作資料規則。

## 介面與互動

既有編年面板擴充為三個可預測入口：

- `J`：村落編年
- `L`：今日回音
- `R`：關係歷程

關係歷程模式沿用現有三個控制按鈕：上一位、下一位、類型篩選。居民順序為全部、艾莉絲、鮑伯、查理、黛安娜、艾瑞克；類型順序為全部、關係、記憶、故事。畫面顯示目前篩選、最近事件與可讀的數值變化。沒有符合資料時顯示具體指引，不呈現空白面板。

所有按鈕維持至少 44px 高、清楚文字標籤、disabled 狀態與 tooltip；不以顏色作為唯一狀態指示。面板沿用暖色紙張、墨色文字與既有按鈕樣式，避免引入新的裝飾語言。

## 驗收

- 結構化關係、記憶與故事事件可建立、查詢、篩選並深拷貝。
- 關係前後值與實際 runtime 狀態一致。
- 舊時間軸資料可載入；惡意或超大 metadata 被正規化或拒絕。
- UI 三種模式、快捷鍵、居民與類型切換皆可操作。
- 視覺 QA 新增 `relationship_history.png` 實機 GPU 截圖。
- 完整測試、結構檢查、安全掃描、release build 與可攜版 smoke test 全數通過。
