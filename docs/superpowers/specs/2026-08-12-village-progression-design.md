# Echo Village 村落進展系統設計

## 目標

將既有的聲望、任務、互動、記憶與世界事件整合成玩家可理解、可追蹤且會持久保存的長期進展。此功能作為 1.2.0 的作品集級更新。

## 候選方案與決策

1. 季節系統：畫面辨識度高，但需要大量額外美術與全年內容才能避免只有換色。
2. 擴充地圖：增加遊戲時數，但對既有 AI 架構的展示提升有限。
3. 村落聲望、成就里程碑與進度手札：直接串起現有系統、可清楚展示資料驅動架構，且容易進行確定性測試。

採用方案 3。

## 功能範圍

- `ProgressionService` 是不依賴場景的純邏輯服務。
- 聲望分為五級：陌生旅人、熟悉面孔、值得信賴、村落支柱、回音守望者。
- 成就採 JSON 定義，條件只讀取權威世界狀態，不直接修改背包、關係或任務。
- 1.2.0 包含六項成就：第一道回音、慷慨之心、林間信使、藥草採集者、危機見證者、村落支柱。
- 解鎖只能發生一次；重新評估或載入存檔不得重複解鎖或重複發出通知。
- 解鎖狀態、統計與最近解鎖時間隨世界存檔保存；舊版存檔以安全預設值補齊。
- 玩家按 `P` 開啟「村落手札」。面板顯示聲望、稱號、下一級進度、成就完成數與逐項條件。
- 頂部 HUD 顯示聲望與稱號；解鎖時以既有互動回饋卡和音效通知。

## 架構與資料流

`data/progression/achievements.json` 定義成就；`ProgressionService` 提供預設狀態、聲望等級、條件評估與唯一路徑的解鎖結果。`GameManager` 在互動、任務、採集、事件與交易等狀態改變後呼叫評估，保存結果並透過 `EventBus.progression_unlocked` 發送唯讀快照。`ProgressionPanel` 只接收快照並呈現，不自行判斷規則。

## UI/UX

- 延續紙張、苔綠、墨色與淡紫的既有繪本設計 token。
- 640×480 中央模態，標題與摘要先於完整清單，降低資訊負擔。
- 使用文字「已完成／未完成」搭配色彩，避免只靠顏色傳達狀態。
- 關閉按鈕高度至少 44px，支援 `P`、`Esc` 與滑鼠。
- 面板開啟時暫停模擬；關閉後恢復原本速度。

## 錯誤與相容性

- 無效或未知條件不解鎖，回傳穩定結果且不造成執行期錯誤。
- 缺少 progression 欄位的舊存檔使用預設狀態，保留既有 community renown。
- 重複事件、重複採集或重複反序列化不會產生重複成就。
