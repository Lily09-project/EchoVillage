# Echo Village｜作品集 Case Study

## 專案定位

Echo Village 是以 Godot 4 與 GDScript 完成的繁體中文 2D 生活模擬 RPG。目標不是做一個能啟動的 demo，而是展示從遊戲設計、代理 AI、資料架構、UI/UX、存檔到測試與 Windows 發行的完整產品流程。

## 設計問題

生活模擬中的 NPC 容易只像定時移動的裝飾。此專案要讓居民的行動具備原因、後果與可追溯性，同時保持離線、可測試，不把核心玩法綁在不可控的雲端模型。

## 解法

每位居民以需求、個性、作息、資源與事件情境計算 Utility 分數，從十種 Action 中選擇行為；獨立 State Machine 與 Navigation Agent 執行決策。互動會建立結構化記憶，記憶能改變關係並在居民間傳播，因此贈禮、偷竊與危機不只改一個數值，而會成為村落故事。

## 我完成的系統

- 資料驅動的五位自主居民與十種 Utility Action。
- NPC 對 NPC 關係網、長期記憶、衰減、傳播與情緒後果。
- 動態事件、關係價格、雙向交易、庫存、配方與多階段任務。
- 村落／森林探索、Godot 2D Navigation 與雙層卡住復原。
- 完整主選單、設定、暫停、HUD、背包、地圖、任務與交易 UX。
- 自動存檔、版本化序列化、舊檔遷移與不重複任務獎勵。
- 五級村落聲望、六項資料驅動成就與可持久保存的村落手札。
- 首次旅程導覽：三步驟、可略過、Esc 關閉、偏好持久化與暫停選單 F1 重開，降低新玩家理解成本。
- 87 項自動測試、十二張 GPU 視覺 QA、CI quality gate 與 portable Windows 發行管線。

## 關鍵工程決策

1. **可解釋 AI**：Action 分數能被 Debug 面板觀察，便於平衡與除錯。
2. **資料與程式分離**：NPC、事件、物品、任務和地點均由 JSON 擴充。
3. **原子狀態更新**：交易與製作先驗證完整條件，再一次更新雙方狀態。
4. **防假綠燈測試**：測試器除斷言外還掃描 Godot runtime 錯誤。
5. **免安裝交付**：沒有 Export Templates 時採 portable runtime + PCK，消費者仍可直接雙擊。
6. **以首次體驗驗收產品**：導覽只保存偏好、不污染世界存檔；測試同時覆蓋完成、略過、Esc 與從暫停選單重開。

## 問題與修復案例

- 原啟動器依賴系統 PATH；改為隨專案附帶 Godot runtime。
- 交易初版是快捷買麵包；重做為完整選品、買入、出售、庫存與價格視窗。
- 世界事件用單日分鐘結束，跨午夜會錯；改為 remaining-minutes 生命週期。
- 新 AI 腳本首次匯入造成 Autoload 依賴為空；以編輯器編譯閘門修復並讓測試捕捉 runtime error。
- Windows 中文 BAT 在部分語系被錯誤解析；建置腳本改為 ASCII 指令，中文留在產品內容。

## 成果

專案形成可直接交付的 1.2.0 Windows 作品：核心玩法可完整遊玩，聲望與資料驅動成就讓玩家選擇形成長期進展；所有主要功能有測試證據、UI 有實機視覺證據，並保留清楚的擴充邊界。這個作品可用來展示 Gameplay Engineering、AI Architecture、Progression Design、Systems Design、UI Implementation、Testing 與 Release Engineering。

## 建議展示順序（3–5 分鐘）

1. 新遊戲首次導覽：展示三步驟 onboarding、可略過流程與 F1 重開入口。
2. 主選單與設定：說明消費者流程及自動存檔。
3. 村落正午：觀察居民需求、作息與 Utility 決策。
4. 贈禮／偷竊：展示記憶、關係與村落編年。
5. 交易與製作：展示原子經濟流程。
6. 林間回音：展示跨地點任務鏈。
7. F3 面板與測試報告：展示可解釋 AI 與工程品質。
